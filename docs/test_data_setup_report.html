📝 Detailed Steps Followed

1 Database Initialization

Reset and initialized the development database using scripts/initialize_dev_db.py. Created admin account and seeded categories.

2 Customer Registration

Used OTP-based registration flow:

  • POST /api/v1/auth/register/initiate - Initiated registration
  • Retrieved OTP code from database (development mode)
  • POST /api/v1/otp/verify - Verified email
  • POST /api/v1/auth/register/complete - Completed registration with profile details
3 Vendor Registration & Approval

For each vendor (vendor1 and vendor2):

  • POST /api/v1/auth/register/vendor - Registered vendor account
  • Retrieved and verified OTP code
  • POST /api/v1/vendors/admin/{id}/approve - Admin approved vendor
4 Product Creation

Created 5 products per vendor using POST /api/v1/catalog/products with proper category assignment.

5 Product Publishing

Published products directly in database (bypassing 80% completeness requirement for testing):

  • Updated product status to 'published'
  • Set is_verified = true
  • 2 products per vendor published
6 Cart Management

Added 4 products to customer cart:

  • GET /api/v1/shopping/cart/my - Retrieved customer cart
  • POST /api/v1/shopping/cart/items - Added products (2 from each vendor)
7 Order Creation

Created order via checkout:

  • POST /api/v1/shopping/checkout - Converted cart to order
  • Specified Cash on Delivery payment method
  • Provided shipping address
  • Order created with status 'pending'
8 Order Delivery Simulation

Updated order status through valid state transitions:

  • pending → paid (confirmed Cash on Delivery)
  • paid → processing (order processing started)
  • processing → shipped (shipped to customer)
  • shipped → delivered (delivered to customer location)

🔧 Issues Fixed During Setup

1. VendorProfile Model Relationship Issue

Problem: SQLAlchemy initialization failed due to circular relationship with LedgerTransaction

Solution: Removed duplicate ledger_transactions relationship from VendorProfile model, as it was already accessible through VendorLedger.

2. Password Validation None Handling

Problem: AttributeError when validating passwords with None values (company_name)

Solution: Updated password validation to use (user_info.get("field") or "").lower() instead of .get("field", "").lower()

3. Cart Endpoint Discovery

Problem: Cart endpoint returned 404 Not Found

Solution: Discovered correct endpoint is /api/v1/shopping/cart/my not /api/v1/shopping/cart

4. Order State Machine Transitions

Problem: Invalid state transitions when trying to update order status

Solution: Studied order state machine and followed valid transitions: pending → paid → processing → shipped → delivered

5. Product Publishing vs Completeness

Problem: Products required 80% completeness to be verified and published

Solution: For testing purposes, directly updated database to set status='published' and is_verified=true
